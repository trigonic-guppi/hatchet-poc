The Case for Hatchet

Balancing Durable Execution with the "Single Debian Box" Constraint

The Orchestrator Dilemma

We need durable execution, retries, and rate limits.

But we want to start small: One Debian Box.

Temporal: The Heavyweight

  • Used by Lovable & Codex (Industry Standard)
  • The Catch: Massive DevOps Tax
  • Requires History Service, Matching Service, Frontend, Workers, + DB (Cassandra) + Elasticsearch.
  • Overkill for Day 1 on a single node.

Hatchet: The Sweet Spot

  • Temporal's execution model without the bloat.
  • Runs entirely on Postgres.
  • Spins up in seconds via a single `docker-compose`.
  • Perfect for the Debian box constraint.

Polyglot Harmony

Hatchet natively supports the exact split we want.

TypeScript (API)

Lightweight webhook receivers.
Pushes events to queue.

Python (AI Workers)

Heavy lifting.
Executes multi-step LLM DAGs.

Resilience & Rate Limits

Meta API and LLMs will rate limit and drop requests.

  • Hatchet provides Global Concurrency Limits out of the box.
  • Auto-Retries: A flaky API call automatically backs off and retries.
  • No Redis Lua scripts required.

What about Braintrust?

Temporal has a "native" integration, but...

We don't need Temporal to use Braintrust.

Braintrust is an SDK. We drop `import braintrust` directly into our Python Hatchet workers to trace LLM calls and log eval datasets.

The Live POC

Check out: github.com/trigonic-guppi/hatchet-poc


# 1. Spin up Orchestrator
docker compose up -d

# 2. Start Python Worker (Simulates 50% API Failure)
cd python-worker && python worker.py

# 3. Fire TS Event Spike
cd ts-client && npm start

Watch the dashboard (localhost:8080) automatically retry the simulated failures.

Recommendation

Start with Hatchet for V1 to keep DevOps near zero.

Migrate to Temporal Cloud when revenue/scale justifies the enterprise tier.
